# ملتقى المسك القرآني

نظام ويب متكامل (عربي RTL) لإدارة الحلقات القرآنية: مسؤول إداري، مشرفون (ذكور / إناث / كيدز)، طلاب، تسميع، امتحانات سور، تقويم، وتقارير.

| الطبقة | التقنية |
|---|---|
| الواجهة | React 18 + Vite + React Router + FullCalendar |
| الخادم | Node.js 20+ و Express 5 |
| قاعدة البيانات | Supabase (PostgreSQL) |
| النشر | Render — خدمة واحدة تخدم الـ API والواجهة معًا |

---

## 1) ما الذي يتضمنه النظام

### المسؤول الإداري (حساب واحد ثابت)
- **المشرفون:** إضافة (يُولَّد اسم المستخدم وكلمة المرور تلقائيًا ويظهران في صفحة المشرف)، تعديل، **فصل** (يُحفظ في «سجل المفصولين» ويمكن إرجاعه)، **حذف نهائي** مع تحذير وكتابة اسم المشرف للتأكيد، ونقل طلابه لمشرف آخر عند الحذف. توليد كلمة مرور جديدة.
- **لوحة التحكم:** عدد الطلاب، الطلاب تحت التحذير، عدد المشرفين، نسبة الالتزام الشهرية، صفحات وامتحانات الشهر، مخطط آخر 14 يومًا، المواعيد القادمة، أداء المشرفين، آخر النشاطات.
- **الطلاب:** جدول مع بحث (يتجاهل الهمزات والتشكيل) وفلاتر. عند فتح الطالب: اسم مشرفه، **عدد التسميعات المحددة / التزم فيها / لم يلتزم**، جدول **امتحانات السور** (العلامة + التاريخ + ناجح/راسب)، سجل التسميع، التحذيرات.
- **التقويم:** كل مواعيد كل المشرفين (عرض) مع فلتر بالمشرف.
- **التقارير:** التقرير الشهري للمشرف (مطابق للتقرير الورقي — طباعة/PDF وتصدير Excel)، الطلاب تحت التحذير، امتحانات السور، أداء المشرفين.
- **سجل النشاط** لكل ما يحدث في النظام، و**الإعدادات**، و**الملف الشخصي** (تعديل المعلومات وكلمة المرور).

### المشرف (ذكور / إناث / كيدز)
- الواجهة تتكيّف مع النوع: «الطلاب» / «الطالبات» / «الأطفال»، ولون مختلف لكل نوع، وجنس الطالب يُحدَّد تلقائيًا (والكيدز يختار).
- إضافة وتعديل الطلاب. **الفصل والحذف بموافقة الإدارة فقط**: يرسل المشرف «طلب فصل» أو «طلب حذف» مع السبب (القسم 8).
- جدول طلابه، وعند فتح الطالب: **حجز تسميع / حجز امتحان سورة / تسجيل تسميع سابق / تحذير**.
- **التقويم:** نافذة منبثقة للحجز (بالضغط على يوم أو ساعة)، سحب الموعد لإعادة جدولته، تعديل، إلغاء، حذف.
- **تسجيل النتيجة:** «تم» (يرتفع عدّاد الطالب بالصفحات)، «لم يلتزم»، وللامتحان تُسجَّل العلامة في سجل الطالب.

### حماية الأوقات (التوقيت)
- لا يمكن حجز موعدين متداخلين لنفس الطالب، ولا **جلستين مختلفتين** لنفس المشرف في نفس الوقت — يُفحص في الخادم **وفي قاعدة البيانات** (قيد `EXCLUDE`). الجلسة الجماعية (عدة طلاب مع نفس المشرف) مسموحة، ولا يوجد أي قيد بين المشرفين المختلفين.
- لا حجز في وقت مضى، ولا خارج ساعات الدوام (قابلة للتعديل من الإعدادات)، والموعد يجب أن ينتهي في نفس اليوم.
- لا يمكن تسجيل «تم/لم يلتزم» قبل حلول وقت الموعد.
- كل الأوقات تُحفظ UTC وتُعرض/تُفحص بمنطقة `Asia/Hebron` (قابلة للتغيير عبر `APP_TIMEZONE`).

### «تحت التحذير» (تلقائي + يدوي)
يصبح الطالب تحت التحذير إذا: عدم التزام ≥ 2 خلال 30 يومًا، أو لم يسمّع منذ 14 يومًا، أو وُضع عليه تحذير يدوي. الأرقام قابلة للتعديل من **الإعدادات**.

### إضافات لم تطلبيها (لتماسك النظام)
سجل نشاط كامل • إعدادات النظام • تحذيرات يدوية • نقل طالب بين المشرفين • تسجيل تسميع سابق • تصدير CSV/Excel وطباعة • معدّل محاولات دخول محدود (حماية من التخمين) • حماية الجلسات بكوكي `HttpOnly` • إيقاف المشرف المفصول فورًا حتى لو كان داخل النظام • واجهة متجاوبة للجوال.

## 2) التشغيل محليًا في IntelliJ IDEA

**المتطلبات:** Node.js 20 أو أحدث، وحساب Supabase.

1. افتح **مجلد المشروع الرئيسي** `masak-quran-forum` في IntelliJ (`File → Open`).
2. جهّز قاعدة البيانات (الخطوة 3 أدناه) واحصل على `DATABASE_URL`.
3. أنشئ ملف `server/.env` بنسخ `.env.example` وعبّئ القيم (`DATABASE_URL`, `JWT_SECRET`, `CREDENTIALS_KEY`, `ADMIN_PASSWORD`).
4. افتح **Terminal** داخل IntelliJ (تبويبان):

```bash
# التبويب 1 — الخادم (المنفذ 4000)
cd server
npm install
npm run migrate      # مرة واحدة: ينشئ الجداول في Supabase
npm run dev
```

```bash
# التبويب 2 — الواجهة (المنفذ 5173)
cd client
npm install
npm run dev
```

5. افتح **http://localhost:5173** وسجّل دخولك بحساب المسؤول: `ADMIN_USERNAME` / `ADMIN_PASSWORD`.

> في IntelliJ Ultimate يمكنك أيضًا إنشاء Run Configuration من نوع **npm** لكل من `server → dev` و`client → dev`.
> التوليد السريع لمفتاح سري: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`

## 3) إعداد Supabase

1. أنشئ مشروعًا جديدًا في [supabase.com](https://supabase.com) واحفظ **كلمة مرور قاعدة البيانات**.
2. اضغط زر **Connect** أعلى الصفحة ← **Session pooler** وانسخ رابط الاتصال:
   `postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-0-….pooler.supabase.com:5432/postgres`
   - **استخدم Session pooler وليس Direct connection**: الاتصال المباشر يعمل على IPv6 فقط وRender لا يدعمه.
   - إن احتوت كلمة المرور رموزًا خاصة (`@ # / : %`) فحوّلها بترميز URL (مثال `@` ← `%40`) أو اختر كلمة مرور من حروف وأرقام.
3. ضع الرابط في `DATABASE_URL`.
4. أنشئ الجداول بأحد طريقين:
   - `npm run migrate` من مجلد `server` (الأسهل)، **أو**
   - انسخ محتوى `database/schema.sql` ثم كل ملف في `database/migrations/` (بالترتيب) إلى Supabase ← **SQL Editor** ← Run.
   (`npm run migrate` يتتبع الترحيلات المطبقة في جدول `schema_migrations` فلا يكررها.)

الجداول تُنشأ مع **RLS مفعّل بلا سياسات**، أي أن مفتاح `anon` العام في Supabase لا يستطيع قراءة أي شيء؛ الخادم وحده يصل للبيانات. **لا تضع أي مفاتيح Supabase في الواجهة.**

## 4) النشر على Render

1. ارفع المشروع إلى **GitHub** (ملف `.gitignore` جاهز ويستثني `.env` و`node_modules`).
2. في Render: **New → Blueprint** واختر المستودع (يقرأ `render.yaml` تلقائيًا)، **أو** **New → Web Service** يدويًا بهذه الإعدادات:

| الحقل | القيمة |
|---|---|
| Runtime | Node |
| Build Command | `npm run render-build` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |

3. أضف متغيرات البيئة (Environment):

| المتغير | القيمة |
|---|---|
| `NODE_ENV` | `production` |
| `NODE_VERSION` | `22` |
| `DATABASE_URL` | رابط Session pooler من Supabase |
| `JWT_SECRET` | نص عشوائي 48+ حرفًا (Blueprint يولّده تلقائيًا) |
| `CREDENTIALS_KEY` | نص عشوائي (Blueprint يولّده تلقائيًا) — **لا تغيّره لاحقًا** |
| `ADMIN_USERNAME` | مثال `admin` |
| `ADMIN_PASSWORD` | كلمة مرور قوية للمسؤول |
| `APP_TIMEZONE` | `Asia/Hebron` |

4. اضغط Deploy. أمر البناء يثبّت الحزم ويبني الواجهة وينفّذ الـ migration على Supabase تلقائيًا، ثم يُنشئ الخادم حساب المسؤول عند أول تشغيل.

**ملاحظات:**
- الخطة المجانية في Render تدخل في «سبات» بعد 15 دقيقة من عدم الاستخدام وأول فتح بعدها يستغرق ~30–60 ثانية. للاستخدام الفعلي يُنصح بخطة مدفوعة.
- نسيتِ كلمة مرور المسؤول؟ ضعي كلمة جديدة في `ADMIN_PASSWORD` مع `ADMIN_FORCE_RESET=true`، أعيدي النشر، ثم احذفي `ADMIN_FORCE_RESET`.


## 7) الأمان — باختصار
- كلمات المرور مخزّنة بـ **bcrypt** للتحقق، وبنسخة **مشفّرة AES-256-GCM** فقط لتمكين المسؤول من عرض بيانات دخول المشرف. إذا غيّر المشرف كلمته بنفسه تُحذف النسخة المشفّرة ولا تعود ظاهرة للمسؤول.
- جلسات JWT في كوكي `HttpOnly` + `SameSite=Lax` (+ `Secure` في الإنتاج)، مدتها 7 أيام.
- المشرف لا يرى ولا يعدّل إلا طلابه ومواعيده (يُفحص في الخادم في كل طلب).
- رؤوس أمان (Helmet/CSP)، وتحقق صارم من المدخلات (Zod)، واستعلامات مهيّأة (لا SQL injection).

## 8) التحسينات الإدارية (الإصدار 2)

### الأدوار والصلاحيات (تُفحص في الخادم لكل نقطة API)
| الدور | يصل إلى |
|---|---|
| المسؤول الإداري | كل شيء |
| المشرف | طلابه فقط، مواعيده، تقاريره، طلباته للإدارة، سجله، الإعلانات الموجهة له، التواصل مع الإدارة |
| **مشرف التسجيل والقبول** (جديد) | القبول والتسجيل فقط + الإعلانات الخاصة به + التواصل مع الإدارة. **لا** يصل للطلاب أو المشرفين أو التحليلات أو الإعدادات أو التحذيرات |

> الطلاب لا يملكون حسابات دخول في هذا النظام (هم سجلات يديرها المشرفون)، لذا لا يمكنهم رؤية أي إعلان إداري.

### طلبات حذف/فصل الطلاب
- المشرف لا يستطيع الحذف أو الفصل مباشرة (الخادم يرفض بـ 403). يرسل **طلب حذف** أو **طلب فصل** مع السبب والملاحظات.
- المسؤول يوافق أو يرفض من صفحة **طلبات المشرفين**، ويُشعَر المشرف بالقرار. كل الطلبات والقرارات محفوظة.
- **الحذف أصبح ناعمًا**: يختفي الطالب من القوائم والإحصائيات وتبقى كل سجلاته، ويمكن للمسؤول **استعادته**.

### التحذيرات الرسمية للمشرفين
- البريد الإلكتروني **إلزامي** عند إنشاء المشرف، ويُرسل رابط لتأكيد ملكيته (صالح 48 ساعة). تغيير البريد يتطلب تأكيدًا جديدًا. يمكن للمسؤول التأكيد يدويًا مع ذكر طريقة التحقق (يُسجَّل في السجل).
- التحذير يحتوي: السبب، الملاحظات، التاريخ والوقت، المُصدِر، الحالة (ساري/ملغى). يصل للمشرف في لوحته وعلى بريده المؤكد.
- **التحذير الثاني الساري ← إيقاف تلقائي** لصلاحيات المشرف (الحد قابل للتعديل) مع إشعار المشرف والإدارة، وإلغاء مواعيده القادمة. الطلاب يبقون ويمكن نقلهم.
- إلغاء تحذير خاطئ يُسجَّل ويبقى في التاريخ، ولا يعيد التفعيل تلقائيًا.

### المتابعة الآلية لاكتمال السجلات
- في كل **فترة إبلاغ** (افتراضيًا أسبوعية تبدأ السبت): يجب تسجيل نتيجة كل موعد بعد وقته، وأن يكون لكل طالب نشط تسميع مسجّل واحد على الأقل.
- بعد نهاية الفترة **مهلة تصحيح** (يومان افتراضيًا) مع تنبيه للمشرف بالبنود الناقصة بأسماء الطلاب.
- عند انتهاء المهلة تُقيَّم الفترة **مرة واحدة فقط**: المخالفة الأولى ← تذكير، الثانية ← تحذير رسمي، الثالثة ← تحذير ثانٍ ← إيقاف.
- لا تُقيَّم: الإجازات المعتمدة، الفترات المعفاة، الطلاب الذين لم يبدؤوا، المشرف الذي انضم بعد بداية الفترة، وأي فترة قبل تاريخ تفعيل الميزة (لا عقوبات بأثر رجعي).
- كل القيم قابلة للتعديل من **الإعدادات**، والإجازات والأعذار من صفحة **متابعة السجلات**.

### تحليلات الأداء (كل 14 يومًا)
- تقرير يُولَّد تلقائيًا بعد كل فترة 14 يومًا ويُحفظ، مع إشعار للمسؤول. وتحليل مخصص لأي فترة.
- **الحفظ الجديد = صفحات التسميعات المكتملة من نوع «حفظ جديد» فقط** — المراجعة لا تُحتسب حفظًا جديدًا.
- إجمالي محفوظ الملتقى، ترتيب الطلاب تصاعديًا وتنازليًا، ترتيب المشرفين، المقارنة بالفترة السابقة ونسب التغير، الطلاب بلا تقدم، اتجاه 8 فترات، مقارنة الفئات (ذكور/إناث/كيدز)، المشاركة واكتمال السجلات.
- تصدير **Excel حقيقي (.xlsx)** بأوراق متعددة، و**PDF عبر الطباعة** («حفظ كـ PDF» من المتصفح يحافظ على العربية).

### التواصل مع الإدارة
محادثات خاصة (استفسار/شكوى/اقتراح/طلب) بواجهة دردشة، حالة مفتوحة/قيد المعالجة/مغلقة، علامات القراءة، عدّاد غير المقروء. التحديث شبه فوري عبر استطلاع خفيف (كل 8 ثوانٍ داخل المحادثة) يتوقف عند إخفاء التبويب — مناسب للاستضافة المجانية.

### الإعلانات والتعاميم
جداول التسميع، الاجتماعات، الإعلانات المهمة، تحديث السياسات، التعليمات، التنبيهات العاجلة. تثبيت، تاريخ حدث، تاريخ انتهاء، جمهور (المشرفون / مشرفو التسجيل / الكل)، مقروء/غير مقروء، وسجل تسليم البريد. البريد يُرسل **مرة واحدة فقط** لكل مستلم (حتى عند تعديل الإعلان).

### التقويم
- **جلسات جماعية**: عدة طلاب مع المشرف في نفس الوقت تظهر كحدث واحد مع قائمة الطلاب. مشرفون مختلفون في نفس الساعة يظهرون مستقلين بلون كل مشرف.
- مواعيد **متكررة** (يومي/أسبوعي/كل أسبوعين) بنفس الساعة المحلية حتى مع التوقيت الصيفي، وإلغاء السلسلة القادمة.
- نقل الجلسة كاملة أو إلغاؤها، إضافة طالب لجلسة قائمة، فلاتر بالمشرف والفئة والنوع وبحث، عرض يوم/أسبوع/شهر/قائمة، وكل الأوقات بتوقيت فلسطين بغض النظر عن توقيت جهاز المستخدم.

### القبول والتسجيل عبر Google Forms
زر **«إنشاء نموذج تسجيل»** ينشئ Google Form بحقول القبول وجدول Google Sheets **خاص** للاستجابات، ويعرض رابط التسجيل للنسخ. الاستجابات تُستورد تلقائيًا (وبزر «مزامنة الآن»)، كل استجابة مرة واحدة فقط، مع **كشف التكرار** (نفس الهاتف والاسم، أو الاسم وتاريخ الميلاد، أو طالب مسجّل). الحالات: جديد / قيد المراجعة / مقبول / مرفوض. **القبول ينشئ سجل الطالب** بنفس مسار إضافة الطلاب ويعيّنه لمشرف متوافق، مع سجل كامل للقرار.

## 9) الترحيلات (Migrations)

- `database/schema.sql`: الأساس (كما كان).
- `database/migrations/001_platform_enhancements.sql`: كل الجداول والأعمدة الجديدة. **إضافي فقط**: لا يحذف أي جدول أو بيانات. يُعدّل قيدين فقط بشكل متوافق: يضيف الدور `registrar` والحالة `removed`، ويستبدل قيد تداخل مواعيد المشرف بقيد يسمح بالجلسات الجماعية.
- التطبيق: `npm run migrate` (من الجذر أو من `server`). يُنفذ كل ترحيل داخل transaction واحدة ويسجّله في `schema_migrations`، مع قفل يمنع ترحيلين متزامنين. على Render يُنفذ تلقائيًا ضمن `render-build`.
- **قبل الترحيل على الإنتاج:** خذ نسخة احتياطية من Supabase (Database → Backups، أو `pg_dump`).

## 10) إعداد البريد — Resend

البريد اختياري: **كل الإشعارات تظهر داخل المنصة دائمًا**. ما دام البريد غير مُعدّ، تُسجَّل الرسائل بحالة «البريد غير مُعدّ» ولا يدّعي النظام أنها أُرسلت (راجع **الإعدادات ← التكاملات**).

1. أنشئ حسابًا مجانيًا في [resend.com](https://resend.com) (الخطة المجانية تكفي: 3000 رسالة/شهر، 100/يوم).
2. **لا يمكن الإرسال من عنوان Gmail.** تحتاج نطاقًا تملكه (مثل `misk-quran.org`). في Resend: **Domains → Add Domain**.
3. أضف سجلات DNS التي يعرضها Resend عند مزوّد النطاق:
   - **SPF** (TXT/MX على `send.your-domain`) و**DKIM** (TXT `resend._domainkey`) — كما يعرضها Resend حرفيًا.
   - **DMARC** (موصى به): سجل TXT باسم `_dmarc` وقيمة `v=DMARC1; p=none; rua=mailto:misk.quran26@gmail.com`
   - انتظر حتى تظهر الحالة **Verified**.
4. **API Keys → Create** بصلاحية *Sending access* فقط.
5. على Render (Environment): `RESEND_API_KEY`، `EMAIL_FROM=noreply@your-domain`، `EMAIL_REPLY_TO=misk.quran26@gmail.com`، ثم `EMAIL_NOTIFICATIONS_ENABLED=true`.
6. من **الإعدادات ← التكاملات** أرسل رسالة تجريبية وتحقق من وصولها.

اسم المرسل: «إدارة ملتقى المسك القرآني»، والردود تذهب إلى `misk.quran26@gmail.com`. لا يُخزَّن ولا يُطلب أي كلمة مرور لـ Gmail.

**الموثوقية:** الرسائل تُحفظ في `email_outbox` داخل نفس transaction الإجراء الإداري ثم تُرسل في الخلفية، مع مفتاح منع تكرار (`dedupe_key` + `Idempotency-Key` لدى Resend)، وإعادة المحاولة مع تأخير متزايد للأخطاء المؤقتة (429/5xx) حتى 6 مرات، واحترام حد الإرسال (رسالة كل 0.6 ثانية). فشل البريد لا يُلغي أي إجراء إداري.

## 11) إعداد Google Forms و Sheets

1. [Google Cloud Console](https://console.cloud.google.com) ← أنشئ مشروعًا (مجاني، بلا بطاقة دفع).
2. **APIs & Services → Library** وفعّل: **Google Forms API** و **Google Sheets API** و **Google Drive API**.
3. **OAuth consent screen**: نوع *External*، أضف `misk.quran26@gmail.com`، والنطاقات: `forms.body`، `forms.responses.readonly`، `drive.file`.
   - انشر التطبيق (**Publish app → In production**). يظهر تنبيه «تطبيق غير موثّق» عند الربط — اضغط *Advanced → Continue*. بدون النشر تنتهي صلاحية الربط كل 7 أيام.
4. **Credentials → Create OAuth client ID** من نوع *Web application*، و**Authorized redirect URI**:
   `https://<your-app>.onrender.com/api/google/oauth/callback`
   (ومحليًا: `http://localhost:4000/api/google/oauth/callback`)
5. ضع `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` على Render (و`APP_URL` أو `GOOGLE_REDIRECT_URI` محليًا).
6. سجّل الدخول كمسؤول ← **الإعدادات ← التكاملات ← ربط حساب Google** وادخل بحساب الملتقى.

الأمان: رمز التحديث يُحفظ **مشفّرًا** (AES-256-GCM) في جدول منفصل. نطاق `drive.file` يسمح للتطبيق بالملفات التي أنشأها فقط، والجداول لا تُشارك علنًا. النموذج نفسه عام بطبيعته (رابط التسجيل).

## 12) الجدولة — Supabase Cron

خادم Render المجاني ينام، لذا لا نعتمد على المؤقتات داخل Node وحدها:
1. أضف `CRON_SECRET` على Render (يُولَّد تلقائيًا من `render.yaml`) وانسخ قيمته.
2. Supabase → **Database → Extensions**: فعّل `pg_cron` و `pg_net`.
3. افتح `database/supabase_cron.sql`، ضع السر ورابط الخدمة مكان `<CRON_SECRET>` و`<APP_URL>`، ونفّذه في **SQL Editor** (يُحفظ السر في Supabase Vault).
4. كل ساعة يستدعي Supabase `POST /api/cron/tick` (مهلة 120 ثانية لاستيقاظ الخادم). يُنفذ: المتابعة، التقارير الدورية، مزامنة نماذج Google، الإعلانات المجدولة، وإرسال البريد المتأخر.

كل المهام **تعويضية وآمنة للتكرار** ومحمية بقفل في PostgreSQL، فلا يضيع شيء ولا يتكرر. يمكن متابعتها من **متابعة السجلات ← سجل التشغيل**.

## 13) الاختبارات

```bash
npm test          # من الجذر (أو من server)
```
تُنشئ الاختبارات قاعدة PostgreSQL **مؤقتة على جهازك** (embedded-postgres) وتحذفها بعد الانتهاء — **لا تلمس قاعدة Supabase أبدًا** حتى لو كان `DATABASE_URL` في `.env`. البريد وGoogle مستبدلان بمحاكاة. لاستخدام قاعدة اختبار أخرى: `TEST_DATABASE_URL=postgres://… npm test`.
